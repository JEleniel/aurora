## Summary

The original Aurora premise was:

```text
Canonical files should be directly readable and editable by humans and agents.
The validator should be the only required tool.
Projections should compensate only for presentation needs.
```

That premise has not held in practice.

The key evidence:

```text
- File-per-element creates too many tiny files.
- Navigating the model becomes difficult for humans and agents.
- Human-readable projections double file count when generated per element.
- Compact agent views still consume too much context.
- Human views contain agent noise; agent views contain human noise.
- Files are not reliably hand-editable.
- Even the system designer has corrupted models through manual editing.
- Stale projections create a drift risk.
```

## Important constraints clarified

Aurora must preserve:

```text
- One Source of Truth
- canonical vocabulary
- strict derivation
- no hidden authoritative state
- no duplicate human/agent facts
- no separate agent-only model
- no arbitrary modeler-defined storage partitioning
- no business/process terminology leaking into technical design
```

The primary consumers are:

```text
- humans
- agents
```

The validator is not a consumer. It exists only to verify that the model remains valid and usable.

## Decision

Aurora should become a **first-order toolkit with canonical model files**, rather than remain a mostly tool-optional file framework.

The revised premise is:

```text
Canonical files must be authoritative and inspectable.
They do not need to be safely hand-editable as the normal workflow.

Tooling becomes the supported interaction surface for humans and agents.
```

## Resulting architecture

```text
Aurora Canon
- model semantics
- canonical vocabulary
- profile mechanism
- identity/path rules
- derivation rules
- validation rules
- canonical element files
- external prose where appropriate
- no hidden authoritative state

Aurora Toolkit
- safe editing
- validation
- linking/refactoring
- indexing
- traversal
- profile-aware editing
- prose association
- view construction
- diagram/report rendering
- MCP or equivalent agent accessor
```

## Key consequences

### File count becomes less important

A tool can load, index, traverse, and organize many files safely. The number of files no longer has to drive the model shape.

### Prose can remain separate

The toolkit can associate prose with model elements transparently, without forcing prose into the core model files.

### Readability moves to tooling

Readability no longer needs to be bolted onto canonical files. The tool can provide readable inspection, navigation, and rendered output.

### Views become modeler-controlled

Instead of relying on a fixed set of predefined static projections, users can construct views, possibly from templates, then render them.

### Stale projections go away

Generated views are disposable outputs:

```text
authoritative truth = canonical model files
projection/view     = generated render output
```

Projections are not edited, not authoritative, and not reconciled manually.

### Agents can receive bounded context

An MCP or similar accessor can expose the same canonical model through controlled operations without creating a separate agent-specific truth layer.

### Profiles become practical

Externalized profiles can define organization- or domain-specific structures while preserving the limited Aurora core.

## Core invariant

The toolkit may:

```text
- edit
- validate
- index
- cache
- render
- traverse
- refactor
- expose access APIs
```

The toolkit may not:

```text
- store hidden authoritative state
- create a second model
- make projections authoritative
- duplicate facts for different consumers
```

## Final decision statement

Aurora should be treated as:

```text
a canonical model plus conforming first-order tooling
```

not:

```text
a pile of manually edited files
```

and not:

```text
an opaque application with hidden state
```

The files remain the One Source of Truth. The toolkit becomes the supported way to interact with, modify, inspect, render, and expose that truth.
